## Key Findings

## 1) Chroma tool query compatibility issue (`$contains` passed into `get(where=...)`)

Representative failure:
- `results/cug_m2_20260308_230032/athos/cug_lang_chroma_gptoss__gptoss__b046b443/nersc_qa.v2/3bd6f3ffc2ad/0/run.json`
- Error text includes:
  - `Error executing tool chroma_get_documents`
  - `Expected where key to be a metadata field name or a logical operator ($and, $or), got $contains in get.`

Interpretation:
- `chroma_get_documents` forwards `where` and `where_document` directly to Chroma `collection.get(...)`.
- `$contains` is a document filter operator, not a metadata `where` operator for this endpoint.
- The agent/tool-call args are likely placing `$contains` in `where` instead of `where_document`.

Relevant implementation:
- `src/athos/tools/chroma/tools.py:376` (`chroma_get_documents`)
- `src/athos/tools/chroma/tools.py:414-418` (`collection.get(ids=..., where=..., where_document=...)`)

## Architecture Note: Tool Failure Behavior

For `langchain_agent` flow:
- The flow wraps `_graph.ainvoke(...)` in a top-level `try/except` and returns `FlowOutput(content=f"Error: {exc}", metadata={"error": True, ...})` on exception.
- See `src/athos/frameworks/langgraph/flows/agent.py:194-214`.
- Graph construction via `create_agent(...)` does not currently pass a custom tool-error recovery policy in this flow wrapper (`src/athos/frameworks/langgraph/flows/agent.py:659-664`).

Operational consequence in this run:
- Tool exceptions surfaced as structured error outputs in many `run.json` records and were marked `execution_error`.

For `smolagents` flow:
- Also has a top-level `try/except` around `self.agent.run(...)` returning `Error: ...` on uncaught exception (`src/athos/frameworks/smolagents/flows/agent.py:195-235`).
- Internal retry behavior may differ inside the SmolAgents library, but once an exception escapes, ATHOS wraps it as flow error output.
